# newt

A terminal emulator for macOS, built from scratch.

**Goal 1 (in progress):** a terminal good enough to be a daily driver — real PTY sessions, xterm-compatible emulation, tabs, splits, scrollback, selection.

**End goal:** a terminal multiplexer designed for AI agents — sessions that share context across tabs, token usage shown alongside the grid, and agent performance visualized.

It is built so Linux and Windows ports are later work rather than rewrites: everything except the UI lives in a portable Rust core.

## Status

`newt` is usable as a daily driver from a build: windows, tabs, and split panes, with typing, scrollback, selection, copy and paste, and find. The one thing left is packaging it as an installable `.app` (Phase 8).

| Phase | | |
|---|---|---|
| 0 | Scaffolding, build pipeline | done |
| 1 | Terminal core: PTY, emulation, scrollback | done |
| 2 | C ABI and grid snapshots | done |
| 3 | Window and CoreText renderer | done |
| 4 | Input encoding | done |
| 5 | Resize and reflow | done |
| 6 | Scrollback, selection, find | done |
| 7 | Tabs, splits, windows | done |
| 8 | `.app` bundling | next |

Verified against zsh with oh-my-zsh and powerlevel10k, vim, htop, less, and tmux — including editing in vim and paging in less entirely from the keyboard, and vim and tmux redrawing correctly after a resize.

Reflow policy: the primary screen rewraps on a width change and the round trip is lossless; the alternate screen is not rewrapped, because full-screen programs redraw themselves and rewrapping their grid would corrupt the frame they drew. The window snaps to whole cells while dragging.

## Architecture

Two halves, split so the port stays cheap:

- **Core (Rust, `core/`)** — PTY and child process, escape-sequence parsing, terminal state, screen model, scrollback, snapshots. Platform-neutral and written once. Wraps [`alacritty_terminal`](https://github.com/alacritty/alacritty) for emulation and [`portable-pty`](https://github.com/wez/wezterm/tree/main/pty) for the PTY, which already covers Windows ConPTY.
- **Shell (Swift, `macos/`)** — windows, tabs, rendering, text shaping, input capture, bundling. Rewritten per platform; that is the cheap half.

A *pane* pairs one core session with its view; tabs and splits compose panes, and nothing above that layer touches a session directly. That is where the end goal attaches: each session carries token counts, cost, model, and agent state as first-class metadata the UI can observe without reaching into the grid. The fields and the plumbing exist and are tested; nothing displays them yet, which is deliberate.

They meet at a narrow C ABI: create a session, write input, resize, read a snapshot of the grid. Plain data only — no callbacks on the hot path and no platform types in any signature. The header (`macos/Sources/CNewt/include/newt.h`) is generated by `cbindgen`, never edited by hand.

Two rules keep the split honest: nothing in the core may reference macOS concepts, and nothing in the shell may implement terminal semantics — if a fix concerns what an escape sequence *means*, it belongs in the core even when the symptom is visual.

## Building

Requires Rust (1.85+) and Xcode. `xcode-select` must point at Xcode.app rather than the Command Line Tools, since `XCTest` ships only inside Xcode.

```sh
./scripts/build.sh            # debug
./scripts/build.sh release
```

Cargo must run before SwiftPM — the Swift target links the core's static library — which is what the script exists to enforce. Running `swift build` alone against a stale library produces undefined-symbol errors.

## Running

```sh
./macos/.build/debug/NewtApp                 # a window running your login shell
./macos/.build/debug/NewtApp "ls -la"        # ...with a command run at startup
```

Typing, Control and Option chords, arrow and function keys, mouse reporting, and paste (⌘V, bracketed when the program asks for it) all work. Dead keys and IME composition go through `NSTextInputClient`; in-progress composition is not drawn in the grid yet.

| | |
|---|---|
| Select | drag; double-click for a word, triple-click for a line, ⌥-drag for a block |
| Copy | ⌘C |
| Paste | ⌘V |
| Find | ⌘F, then Return / ⇧Return; ⌘G and ⇧⌘G repeat |
| Scroll | wheel, ⇧PageUp / ⇧PageDown, ⇧Home / ⇧End |
| Tabs / windows | ⌘T, ⌘N |
| Split | ⌘D right, ⇧⌘D down; ⌘W closes a pane |
| Move between panes | ⌥⌘[ and ⌥⌘] |

Search is literal, not a regular expression — someone looking for `a.out` means those characters. A match is selected and scrolled into view, so search reuses the selection highlight rather than inventing a second one.

Draw one frame to a PNG without opening a window — useful for checking the renderer unattended, and the fastest way to see what a frame actually looks like:

```sh
./macos/.build/debug/NewtApp --render-to /tmp/frame.png "printf '\033[1;31mred\033[0m'"

# Drive it from the keyboard: each argument is a step, <name> is a named key.
./macos/.build/debug/NewtApp --render-to /tmp/frame.png \
    --type "vim /tmp/scratch" "<enter>" "ihello" "<escape>"
```

The core can also be driven with no UI at all:

```sh
cargo run --manifest-path core/Cargo.toml -p newt-cli -- "echo hello"
cargo run --manifest-path core/Cargo.toml -p newt-cli -- --cols 100 --rows 30 --settle 1500 "vim /etc/hosts"
cargo run --manifest-path core/Cargo.toml -p newt-cli -- --trace "echo hi"   # raw PTY traffic
cargo run --manifest-path core/Cargo.toml -p newt-cli -- --trace "vim /tmp/f" --keys "ihi" "<escape>"
cargo run --manifest-path core/Cargo.toml -p newt-cli -- --resize 40 10 "vim /tmp/f"   # SIGWINCH and reflow
```

`--trace` dumps the byte stream in both directions — everything the child receives, whether typed or generated by the terminal answering a query. Terminal bugs are usually invisible in the rendered grid, so this is the first tool to reach for.

A Nerd Font is preferred when one is installed (`MesloLGS NF` and friends), since prompt themes lean on Private Use Area icons that SF Mono and Menlo have no glyphs for.

## Testing

```sh
cargo test --manifest-path core/Cargo.toml     # core
swift test --package-path macos                # shell, through the ABI
```

Core tests must pass without any macOS API involved — that is the continuous proof the port stays viable. If a core test ever needs AppKit, something has leaked into the wrong layer.
