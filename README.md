# newt

A terminal emulator for macOS, built from scratch.

**Goal 1 (in progress):** a terminal good enough to be a daily driver — real PTY sessions, xterm-compatible emulation, tabs, splits, scrollback, selection.

**End goal:** a terminal multiplexer designed for AI agents — sessions that share context across tabs, token usage shown alongside the grid, and agent performance visualized.

It is built so Linux and Windows ports are later work rather than rewrites: everything except the UI lives in a portable Rust core.

## Architecture

Two halves, split so the port stays cheap:

- **Core (Rust, `core/`)** — PTY and child process, escape-sequence parsing, terminal state, screen model, scrollback, snapshots. Platform-neutral and written once. Wraps [`alacritty_terminal`](https://github.com/alacritty/alacritty) for emulation and [`portable-pty`](https://github.com/wez/wezterm/tree/main/pty) for the PTY, which already covers Windows ConPTY.
- **Shell (Swift, `macos/`)** — windows, tabs, rendering, text shaping, input capture, bundling. Rewritten per platform; that is the cheap half.

They meet at a narrow C ABI: create a session, write input, resize, read a snapshot of the grid. Plain data only — no callbacks on the hot path and no platform types in any signature. The header (`macos/Sources/CNewt/include/newt.h`) is generated by `cbindgen`, never edited by hand.

Two rules keep the split honest: nothing in the core may reference macOS concepts, and nothing in the shell may implement terminal semantics — if a fix concerns what an escape sequence *means*, it belongs in the core even when the symptom is visual.

## Building

Requires Rust (1.85+) and Xcode. `xcode-select` must point at Xcode.app rather than the Command Line Tools, since `XCTest` ships only inside Xcode.

```sh
./scripts/build.sh            # debug
./scripts/build.sh release
```

Cargo must run before SwiftPM — the Swift target links the core's static library — which is what the script exists to enforce. Running `swift build` alone against a stale library produces undefined-symbol errors.

## Running

No window yet. Both binaries run a shell headlessly and print the resulting grid:

```sh
cargo run --manifest-path core/Cargo.toml -p newt-cli -- "echo hello"
cargo run --manifest-path core/Cargo.toml -p newt-cli -- --cols 100 --rows 30 --settle 1500 "vim /etc/hosts"
cargo run --manifest-path core/Cargo.toml -p newt-cli -- --trace "echo hi"   # raw PTY traffic

./macos/.build/debug/NewtApp "uname -sm"                                     # same, through the ABI
```

`--trace` dumps the byte stream in both directions. Terminal bugs are usually invisible in the rendered grid, so this is the first tool to reach for.

## Testing

```sh
cargo test --manifest-path core/Cargo.toml     # core
swift test --package-path macos                # shell, through the ABI
```

Core tests must pass without any macOS API involved — that is the continuous proof the port stays viable. If a core test ever needs AppKit, something has leaked into the wrong layer.
